# Prompt Optimization Comparison — V1 vs V2 vs V3

## Overview

This comparison evaluates three prompt versions used to analyse the same Junior AI Support Specialist job description.

The objective was to determine whether increasing prompt structure, constraints, evidence requirements, and evaluation criteria could improve the quality and reliability of an LLM response.

## Experimental Setup

The same job description was used for all three prompt versions.

The prompts were tested using Claude.

### V1 — Basic Prompt

A simple instruction with minimal context and no defined output structure.

### V2 — Structured Prompt

Introduced:

* Role
* Context
* Explicit tasks
* Constraints
* Output format
* Prioritisation
* Instructions to avoid unsupported assumptions

### V3 — Advanced Prompt

Introduced:

* Evidence grounding
* Uncertainty handling
* Separation of evidence and recommendations
* Quality-control rules
* Structured extraction
* Output scoring

## Comparison

| Evaluation Area                 | V1         | V2       | V3       |
| ------------------------------- | ---------- | -------- | -------- |
| Role definition                 | Basic/None | Yes      | Yes      |
| Context                         | Limited    | Detailed | Detailed |
| Task specificity                | Low        | High     | High     |
| Output structure                | Low        | High     | High     |
| Constraints                     | None       | Yes      | Strong   |
| Evidence grounding              | Low        | Moderate | Strong   |
| Handling uncertainty            | Low        | Moderate | Strong   |
| Unsupported assumptions control | Low        | Stronger | Strong   |
| Evaluation framework            | None       | None     | Yes      |
| Quality scoring                 | No         | No       | Yes      |
| Transparency                    | Low        | Moderate | High     |

## Observed Improvements

### V1 → V2

V2 produced a more organised response because the prompt explicitly defined the tasks and required output structure.

The model also avoided performing a skill-gap analysis when applicant information was missing.

### V2 → V3

V3 introduced stronger evidence controls and explicitly separated information supported by the job description from recommendations.

It also required the model to identify ambiguity and uncertainty rather than treating every statement as completely clear.

The addition of a quality-scoring framework made the output easier to evaluate.

## Key Prompt Engineering Lessons

### 1. Specificity Matters

A vague instruction can produce a useful answer, but structured instructions provide greater control over the response.

### 2. Constraints Can Reduce Unsupported Claims

Explicitly telling the model not to invent applicant information reduced unsupported assumptions.

### 3. Output Structure Improves Consistency

Defining the expected sections and tables made the responses easier to inspect and compare.

### 4. Evidence Grounding Improves Transparency

Requiring the model to distinguish evidence from recommendations made it clearer which information came from the job description.

### 5. Evaluation Should Be Designed Into the Workflow

V3 demonstrated that prompt engineering can include not only generation instructions, but also quality-control and evaluation criteria.

## Limitations of the Experiment

This experiment has several limitations:

* Only one job description was tested.
* The experiment primarily used one LLM environment.
* The quality scores were generated by the model itself.
* More test cases would be required to determine whether the improvements generalise across different tasks and models.

## Final Conclusion

The experiment demonstrated that progressively improving prompt structure can produce more controlled, transparent, and evaluable LLM responses.

The progression from V1 to V3 shows how prompt engineering can move from a simple instruction toward a structured system incorporating context, constraints, evidence grounding, uncertainty handling, and evaluation.

This project demonstrates practical understanding of prompt engineering rather than simply demonstrating the ability to write individual prompts.
